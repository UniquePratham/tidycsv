How to clean CSV data: a checklist that works

Cleaning data is not one action - it is a fixed order of checks, run the same way every time, so nothing gets fixed twice or missed entirely. Here is the order, with a free tool for each step.

Before you touch the data

  1. Keep the original. Copy the raw export somewhere read-only. Every cleanup is reproducible only if the input is untouched.
  2. Note where it came from - system, export date, filters applied. Half of all "bad data" questions are answered by the export settings, not the file.
  3. Clean a copy, import a copy. Never point an import wizard at the master file.

The cleaning order

  1. Encoding first: if characters are wrong, every later comparison is wrong. Strip BOMs, repair mojibake, normalize line endings - encoding repair.
  2. Delimiter: confirm the file is what the preview says it is - delimiter converter.
  3. Structure: headers must be unique and non-blank, rows must match the header width, no phantom empty rows - structure repair.
  4. Formatting: trim whitespace, normalize unambiguous dates, keep ambiguous dates untouched - full cleaner.
  5. Validity: flag values that cannot be real (emails without @, numbers with currency symbols where a number is required). Flagging is not fixing: a rejected email tells you which rows need a human decision.
  6. Duplicates: dedupe after formatting, not before - trimming first means Alice and Alice collapse into one row - dedupe.
  7. Validate at the destination: import into a staging record, check row counts and 3-5 known-good records, then promote.

What a cleaned file should look like

id,name,email,joined
1,Alice,a@example.com,2024-01-05
2,Bob,b@example.com,2024-02-17
3,Carol,c@example.com,2024-03-01
  • Unique, non-blank headers in a stable naming style.
  • One date format per column, ISO (YYYY-MM-DD) wherever possible.
  • No leading/trailing whitespace; no empty rows; no duplicates.
  • Row count that matches what the source system said it exported.

Common mistakes

  • Fixing rows one by one in a spreadsheet - unrecorded edits cannot be replayed on the next export. Prefer a tool plus a note of what changed.
  • Deduplicating before trimming - misses whitespace twins.
  • Converting every date aggressively - ambiguous 03/04/2024 silently flips day and month in the wrong hands.
  • Cleaning the master file in place - the next export comparison becomes impossible.
