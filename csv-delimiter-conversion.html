Why the delimiter keeps going wrong

  • Regional settings - Excel in many locales uses ; as the list separator, so "CSV" files are actually semicolon-separated.
  • Cells contain commas - names and addresses with commas push exporters to semicolons or pipes.
  • Tab-separated exports - many systems export .tsv with a .csv extension.
  • Human-edited files - someone changed separators by hand and missed some rows.

The tool auto-detects the delimiter by counting separators outside quotes, lets you override it, and writes the download with the delimiter you selected. Quoting follows the CSV rules: values containing the separator, quotes or newlines are wrapped and internal quotes doubled.

Choosing a target delimiter

  • Comma - default for CSV everywhere; most APIs and importers expect it.
  • Semicolon - Excel in comma-decimal locales when opening directly.
  • Tab - paste into spreadsheets without the import wizard.
  • Pipe - common in data pipelines where commas appear inside values.

After converting

Conversion only changes the separator. Run the full cleaner afterwards if the file also has duplicate rows, whitespace, mixed dates or suspicious emails - a delimiter fix will not remove those.

Questions

How is the delimiter detected?
By counting , ; tab and | outside quoted fields in the first part of the file and taking the most frequent one. You can override it with the selector.
Will my commas inside values survive?
Yes - quoted fields stay quoted, so a value like "New York, NY" is written correctly for any target delimiter.
