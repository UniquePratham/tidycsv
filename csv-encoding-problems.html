What cannot be repaired by guessing

Replacement characters (�) mean bytes were already lost before you got the file - no conversion can recover them. The tool counts them and tells you the honest fix: re-export from the source system as UTF-8. The same applies to a file that was double-encoded or saved as a legacy code page without a marker; guessing the code page on customer data risks silent corruption, so this tool refuses to do it.

Set the encoding right at the source

  • Export as UTF-8 whenever the system offers it; UTF-8 with BOM is acceptable (the BOM is stripped here), plain UTF-8 is cleaner.
  • When saving from a spreadsheet, choose "CSV UTF-8 (comma separated)", not "CSV".
  • For programmatic exports, write encoding="utf-8-sig" only if a consumer requires the BOM (Excel), otherwise utf-8.
