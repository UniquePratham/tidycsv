Repair the structure

What "malformed" normally means

  • Ragged rows - some lines have fewer cells than the header. This tool pads the short rows with empty cells and truncates over-long ones to the header width, then tells you it did.
  • Blank or duplicate headers - a header like name,name, breaks importers that expect unique column names. They are renamed to name, name_2, column_3 and every rename is listed.
  • Empty lines - a blank line in the middle of a file becomes a phantom row in most tools; those rows are dropped and counted.
  • Unescaped quotes - a cell containing " must be written as "" inside a quoted field. If a file was edited by hand and quotes are unbalanced, the parser will run the rest of the file together; the reliable fix is to re-export from the source system, or replace smart quotes (“ ”) with straight ones first.

Wrong delimiter is the other classic cause

A semicolon-separated file opened as comma-separated shows one giant column - and every row then looks "malformed". If your preview shows a single column, the delimiter is wrong: use the delimiter converter to read and re-emit the file with the separator your importer expects.

Repair order that actually works

  1. Confirm the delimiter.
  2. Fix encoding if characters look wrong (encoding repair).
  3. Repair structure with the tool above (headers, ragged rows, empty lines).
  4. Clean contents with the full cleaner.
  5. Import into a copy of the destination, never the live dataset.

Questions

Does repairing change my data values?
Structure only: cells are padded or trimmed to the header width, headers are renamed, empty rows dropped. Values are never invented or reordered.
The preview shows one column - is that a malformed file?
Almost always a delimiter mismatch, not damage. Use the delimiter converter.
The file has unreadable characters instead of the ones above.
That is encoding, not structure - see CSV encoding problems.
